Key Additions Locked In
Native Controls (config/controls/): JSON files use Godot's native JoyButton / JoyAxis / Key names directly (e.g., "JOY_BUTTON_A", "JOY_AXIS_LEFT_Y") loaded straight into InputMap at startup—no custom translation layer.

6-Slot Loadout: Slots 1–4 run the symmetrical starter kit; Slots 5 (Character Special) and 6 (Character Ultimate) are wired into LoadoutData.tres, InputBuffer, and BattleHUD from day one with high-cooldown placeholders for Steven to invent wild mechanics.

Swappable Combat & Block: CombatRules.gd isolates damage and knockback math so you can test standard HP vs. percentage scaling anytime, while FighterBase.gd includes a basic guard state ready to expand into parries or shield-breaks.

Stealth Netcode (netcode/): Completely decoupled from local gameplay via SessionManager and GameEvents, letting you build and test online invites quietly behind the scenes.



# Hex-Hax: Game Design Intent & Collaboration Workflow

## Core Vision
**Hex-Hax** is a 2.5D dark-fantasy melee and magic arena fighter inspired by *Super Smash Bros.* It is rendered in 3D (models, lighting, VFX) with all movement and combat locked strictly to the **2D X/Y plane (`Z = 0`)**. It supports both **Co-op** (team survival/vs. bots) and **PvP** (Free-For-All and 2v2).

## How We Build Together (Modularity First)
* **Engine & Infrastructure:** Core physics, camera framing, hitboxes, input buffering, and netcode are isolated in decoupled GDScript modules.
* **Steven's Sandbox:** All character stats, weapon properties, and ability frame data live inside standalone `.tres` Inspector files and `.json` controller configs. No coding is required to invent characters, tune knockback, or rebalance matchups.
* **Plain-English Code:** Every script is thoroughly commented (variables, functions, and section headers) so anyone can open a file and see exactly how the math and mechanics work.
